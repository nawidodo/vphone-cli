# Stage 2 — Raw Syscall Tracing (v1.0.0 blueprint)

Status: **implemented, compiles for the guest, host-side harness passes.**
On-device verification (arm + capture `ls /` events) is pending an eligible
host — see "On-device verification" below.

## What was built

```
repo/scripts/vphone-traced/
├── vphone-traced.c     # main: CLI, signal handling, arm/pump/print loop
├── trace_event.{c,h}   # kd_buf ABI + debugid classification → vt_event
├── trace_ktrace.{c,h}  # CTL_KERN/KERN_KDEBUG sysctl session control
├── trace_ring.{c,h}    # bounded pre-roll ring (used from stage 3; built in)
├── trace_json.{c,h}    # v1-protocol JSONL emitters (--json)
├── host_test.c         # native assertion harness (no kernel calls)
├── Makefile            # `make hosttest` (macOS), default target (iphoneos)
├── entitlements.plist  # platform-application + no-container
└── vphone-traced.plist # LaunchDaemon (RunAtLoad, KeepAlive=false)
```

Packaging:
- Root `Makefile` gained a `vphone-traced` target (build + `ldid` sign →
  `vm/.vphone-traced.signed`), mirroring `vphoned`.
- `scripts/cfw_install.sh` installs `/usr/bin/vphone-traced` +
  `System/Library/LaunchDaemons/vphone-traced.plist` during CFW install,
  rebuilding when sources are newer (same pattern as the vphoned block).

Deliberate scope exclusions (blueprint §33): no syscall-name decoding, no PID
filtering, no argument decoding, no host CLI integration.

## Build

```bash
cd repo
make vphone-traced          # cross-compile (iphoneos SDK) + sign → vm/.vphone-traced.signed
make -C scripts/vphone-traced hosttest   # native parsing-layer assertions
```

`make vphone-traced` was run: produces a signed Mach-O arm64 binary.
`hosttest` output: `host_test: all assertions passed` (classification of BSD
entry/exit + Mach records, exit-record pid extraction, TRACE_LOST_EVENTS
detection, ring wraparound `wrapped == pushes − capacity`, oldest→newest ring
visit order, JSON shapes for `syscall` and `trace_drop`).

## Install & run (guest)

Provision a `jb`/`dev` VM once (installs the daemon):

```bash
vphone-cli vm create syscall-lab -V jb     # runs cfw_install.sh internally
```

Stage 2 transport is SSH-only by design (blueprint §7 allows SSH for early
prototyping; the vsock 1339 channel lands with stage 7):

```bash
ssh -p 22222 root@<vm-ip>          # jb: root, regular/dev: root too
/usr/bin/vphone-traced --kv
# or: /usr/bin/vphone-traced --json --count 100
```

Expected output while running `ls /` in another SSH session:

```text
ts=12340001 tid=0x81 debugid=0x040c0015      # open entry  (5<<2|1)
ts=12340005 tid=0x81 debugid=0x040c0016      # open exit   (5<<2|2)
ts=12340007 tid=0x81 debugid=0x040c0051      # getpid entry (20<<2|1)
```

`--kv` suffixes `BSD|MACH|META entry|exit`; `--json` emits the blueprint §18
record shape (one object per line). Kernel drop markers
(`debugid=0x07020008`) print `[trace warning] kernel reported dropped events`
and a `trace_drop` JSON record — never silently ignored.

## Fixtures

- `tests/fixtures/raw-trace.txt` — canonical Stage-2 text lines (entry/exit
  pairs for `open`, `getpid`).
- `tests/fixtures/raw-trace.jsonl` — same events through the JSON emitter,
  including a `meta` newthread record and a `trace_drop` record.

Both are generated by the real classification/JSON code paths (see
`host_test.c`), so format regressions break the fixture.

## Implementation notes

- **kd_buf ABI**: 64-byte arm64 record (timestamp + 5×u64 args + u32 debugid
  + u32 cpuid + u64 unused), `_Static_assert`-checked. Verified against
  xnu-11417.140.69 `bsd/sys/kdebug_private.h:258-275`; identical layout
  expected on the xnu-12377.x guest kernels — re-verify if a guest boots with
  truncated records.
- **Debugid constants** (`DBG_BSD=4`, `DBG_MACH=1`, `DBG_*_EXCP_SC=0x0C`,
  `DBG_FUNC_START/END=1/2`, code<<2) are vendored in `trace_event.h` because
  the guest SDK ships no `<sys/kdebug.h>`.
- **BSD exit records carry pid in arg4** (`systemcalls.c:223-224`), so raw
  pid attribution already works for exits without the thread map; entry
  attribution waits for the stage-4 resolver.
- **Session control order**: `KDSETBUF → KDEFLAGS(BUFINIT) → KDSETUP →
  KDSETREG(subclass) → KDENABLE(1)`; teardown `KDENABLE(0) → KDREMOVE`.
  Requires root (`ktrace_configure` EPERM otherwise); the binary refuses to
  run unprivileged with a clear error.
- **Pump loop**: `KDBUFWAIT(50ms)` then `KDREADTR` into a 64 MiB drain buffer,
  classified per record, printed, `fflush` per batch. SIGINT/SIGTERM stop
  cleanly with an event/drop summary on stderr.
